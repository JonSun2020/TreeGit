# TreeGit 验证说明

主要环境为 Windows x64、Python 3、Git for Windows。构建源码需要 .NET 10 SDK；正常便携程序自带运行时。LFS 和 Git Flow 专项需要各自外部组件。

测试在临时仓库写入，部分脚本会关闭所连接的 TreeGit 桌面。每组桌面测试使用独立的程序副本和空 `data/`，不要使用日常运行目录。切换需要不同环境变量的测试时，先等待上一组测试进程完全退出，或换一个新副本；MCP 会连接同目录已经运行的桌面。

## 正常发布构建

```powershell
./build-treegit.ps1 -Destination ./artifacts/TreeGit
```

将输出的程序文件复制到独立测试目录，再运行相应脚本。例如：

```powershell
python tests/mcp_protocol.py <测试副本>/TreeGit.exe <结果目录>/protocol.json
python tests/mcp_integration.py <测试副本>/TreeGit.exe <结果目录>/core
python tests/binary_diff.py <另一测试副本>/TreeGit.exe <结果目录>/binary
python tests/binary_refresh.py <另一测试副本>/TreeGit.exe <结果目录>/binary-refresh
python tests/desktop_soak.py <另一测试副本>/TreeGit.exe <结果目录>/soak 3600
```

`ui_integration.py` 需要前序核心测试生成的 `mcp-results.json`：复制该文件到 UI 结果目录，再传入这个目录。Git 核心测试使用实际提交、文件及引用核对；二进制检查比较实际字节，并等待后台刷新和首个差异定位完成。

二进制测试和持续测试给桌面设置独立 TEMP/TMP，跟踪自己的快照并检查关闭后的清理。正常构建没有测试专用快照字段，不能用空集合代替清理验证。持续报告保留进程 ID、资源采样、请求延迟、快照和失败内容；测试脚本的版本也应与记录对应。

## 集成测试构建

```powershell
./build-treegit.ps1 -IntegrationTests -Destination ./artifacts/TreeGit-QA
```

该构建增加真实控件和工作流的驱动，供设置持久化、认证输入、索引占用、连续冲突、消息恢复、子模块选择等专项脚本使用。正常发布不包含驱动，打包脚本拒绝该构建。

`--integration-probe <临时目录> <报告.json>` 验证原始命令、图谱、bundle、子模块、工作树、LFS 对象传输和 Git Flow。其 Git Flow 检查要求 `git flow version` 可找到 Git Flow Next。不要在业务仓库运行这些写入专项。

## Git 自动检测与内置回退

`GitDiscoveryProbe.csproj` 编译真正的检测器，使用构造的可用、过旧、损坏、挂起程序检查优先级、超时、PATH 与 SSH 配套范围，不修改用户注册表或已安装 Git。可选最后一个参数校验真实便携 `git/cmd/git.exe`。

`git_runtime.py` 需要集成构建、旁边完整的 `git/` 和独立 `data/`。测试在应用子进程中移除 PATH 的 Git 项，并通过**仅集成构建存在**的搜索源覆盖模拟没有系统 Git；它不更改操作系统安装状态。检查真实界面启动、旧路径、内置后重新发现系统 Git、手动路径、组件缺失/损坏提示，以及实际提交、推送、克隆、LFS/Flow/SSH。正常发布不包含该环境变量覆盖。CI 同时执行检测器边界、GUI 回退及正常包检查。

标准构建现在自动准备固定版本、校验过下载文件的便携组件；`package_smoke.py` 包含组件缺失、字节被改动、额外文件和发布隔离的拒绝检查。初次构建需要下载组件，缓存校验通过后可复用；最终用户的 Git 回退不需要下载。

## 真实 SSH 传输

`ssh_transport.py` 使用真实 OpenSSH、回环 SSH 服务及实际 Git 上传/接收协议。服务端测试依赖 Paramiko；不会加入主程序发布包。

先安装测试依赖并构建 `tests/GitSshProxy.csproj`，将 `TREEGIT_TEST_GIT_PROXY` 指向构建后的 `GitSshProxy.exe`。代理运行真实 Git，仅给程序生成的 SSH 命令追加隔离的配置文件，保留原私钥参数，并转发原始输出。代理是测试工具，需可用的 .NET 10 运行时或 SDK。

正常程序使用 `--plain-only` 检查 URI、配置别名、两个身份的克隆、获取和推送。集成构建还检查加密私钥、置顶输入和错误口令重试；`--trust-first-host` 额外检查首次主机指纹确认。SSH 密钥、known_hosts 和配置均在测试目录生成，不修改用户 SSH 文件。

## 自动更新

`UpdaterProbe.csproj` 直接编译实际下载、校验和安装实现，检查续传、服务端忽略 Range、摘要错误、不安全 ZIP、文件占用、写入权限、安装中断和恢复。第二个参数可传入正常发布 ZIP，以核对真实载荷及 Git 清单。

集成构建的 `--integration-update-ui <正常发布ZIP> <临时结果目录>` 使用隔离目录和模拟下载服务，检查真实更新窗口的进度、取消、续传、重新打开、操作忙碌、离线提示、最新版本及高缩放布局。模拟入口和替换故障注入都不包含在正常发布程序内。

所有 `--integration-*` 入口要求测试程序旁边存在独立的 `data` 文件夹，否则拒绝运行。不要把测试程序放在日常使用的安装目录。

`updater_end_to_end.py <旧版正常程序目录> <新版正常程序目录> <新版ZIP> <新结果目录> <UpdaterProbe.exe>` 将旧版复制到全新临时目录，启动真实 GUI，完成替换、重启、启动确认和缓存清理，核对配置、主题、日志及 MCP 配置保留。`--keep-mcp` 同时保持三个 AI 连接；`--old-worker` 使用旧版安装目录中的程序执行更新（旧版须至少为 2026.23.12）；`--expect-rollback` 配合专门构造的启动损坏包检查恢复。禁止将业务安装目录作为结果目录；脚本只关闭自身启动且路径严格匹配的测试窗口。

CI 对正常便携包执行更新内核验证，后续独立任务用同一个程序包检查真实窗口并保存图片。

## 查询输出与认证配置

集成构建的 `command_pipes.py <测试程序> <结果目录>` 使用实际 Git 别名同时写入标准输出和 1 MiB 错误输出，分别检查同步、异步及非零退出。另构造异常认证配置并启用 Git Trace2，检查认证模式读取能结束并回退。每次使用独立配置和目录；超时只清理路径匹配的自有测试进程树。这组检查同时在 CI 执行。

增加 `--streaming` 检查十四个独立读取与文件导出场景：提交、分支哈希、状态、差异、版本对象、文件名和冲突状态等查询在 Git 产生大量错误输出时仍能结束；普通文件与 LFS 内容可以导出，所选版本或文件不存在时不清空原目标，也不遗留本次写入的临时文件。哈希查询也覆盖起始时间为零的边界。

`--pointers` 检查十个 LFS 指针与差异解析场景，包括新增、删除、CRLF、空文件，以及无效大小、数值溢出、短哈希、普通附加文本和未知版本。无效指针应保留可编辑的文本差异。

`--indexes` 检查修改上次提交时使用的索引恢复：大量输入与错误输出同时产生、SHA-256 仓库、包含换行与制表符的路径，以及可执行文件、重命名和符号链接的原始模式；核对真实索引内容，而非只看命令是否返回成功。

`amend_unstage.py` 再走真实界面的“修改上次提交”和取消暂存，分别覆盖 SHA-1 与 SHA-256 的完整选择、首个提交和部分文件选择。它比较完整索引树、原有 HEAD、工作区字节及草稿；另用仅存在于 Git 索引中的换行/制表符文件名核对路径解析，不在 Windows 文件系统创建非法文件。

`RepositoryModeProbe.csproj` 直接编译实际认证实现，使用受控的 Git 包装程序暂缓一次真实配置读取，随后修改配置并使缓存失效。检查旧查询不会重新写入过期模式，以及显式设置始终优先；不访问实际账号和密码。CI 同时执行这两组并发检查。

## 启动与配置恢复

`UiStartupProbe.csproj` 检查缺失或空的 UI 组件及可操作的启动提示。`startup_incomplete.py` 将正常包复制到新目录并故意遗漏组件，确认 MCP 快速返回完整解压提示、保留配置。

`preferences_recovery.py` 使用正常程序的独立副本，分别检查 `null`、损坏 JSON 和文件被锁定。损坏内容保留为备份；暂时无法读取时以只读设置运行，不覆盖原文件。更新首次启动若无法读取原配置，则交给安装器恢复上一版。

`preferences_schema.py` 使用集成构建的独立副本，核对布局、工作区及仓库树等必要部分为 `null` 或包含缺项时可以恢复启动，且备份与原文件逐字一致。这个 CLI 入口不包含在正常程序内；正常程序另用 `preferences_recovery.py` 检查真实窗口。

`repository_config_recovery.py` 检查仓库内部的应用设置与界面状态损坏时仍可打开仓库，保留逐字一致的备份，并在修复无关字段时保留可读取的提交说明。

`close_save_failure.py` 在程序启动后锁住设置或提交说明文件，检查关闭标签会保留未能保存的说明，关闭窗口会提供清楚的返回或退出选择；取消后可继续操作，恢复文件访问后能正常保存退出。也检查暂时读不到的仓库设置可以重新读取，不会永久停留在缓存中的恢复状态。

## 记录失败

`close_during_commit.py` 使用集成构建和暂缓执行的真实 pre-commit 钩子，检查提交期间关闭标签、关闭其他标签、关闭右侧标签、关闭窗口和退出均不会脱离操作；完成提交后标签可以正常关闭。CI 保存实际状态与结果。

`binary_cancel.py` 使用正常程序和 128 MiB 文件，确认比较仍在读取时切换到文本或关闭标签能取消读取，清理全部独立比较快照，并保留同一正常运行的窗口。测试过程不修改业务仓库。

`cold_sync_actions.py <程序> <新结果目录> <GitDelayProxy.exe>` 暂缓真实 Git 的首次分支读取，在仓库信息未加载完成时点击获取、拉取和推送；解除暂缓后应自动打开对应窗口，而非误报没有远程仓库或丢掉点击。包装程序只用于测试，不进入发布包。

给每次失败及修复后的复测使用不同结果目录。先区分程序缺陷、异步操作未完成、环境依赖及测试进程互相干扰，再修改相应部分；不删除首次失败来代替调查。公开验收说明应标明构建源码，不能把旧候选或测试构建的通过记录写成最终发布程序的结果。

`local_auth_failure.py` 使用会返回标准 HTTP 认证错误的本地提交钩子，分别经真实提交界面、MCP `git_action` 和 `git_run` 验证：只执行一次、不产生提交、保留索引，修复钩子后由用户再次提交成功。真实 HTTPS 认证重试另由 `credentials_integration.py --prompt --https` 覆盖。
